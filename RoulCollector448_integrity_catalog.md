# RoulCollector448 — Data-Integrity Capability Catalog

**Repo:** `C:/Users/pc/projects/RoulCollector448` (roulette spin collector: Playwright CDP capture → SQLite → FastAPI dashboard :4480 → LightGBM)
**Purpose of this document:** exhaustive inventory of *how* each integrity mechanism works, as the blueprint for an equivalent system in a different project (poker hand capture).
**Ground rules that shape everything (docs/core-principles.md):** P001 data integrity first; P005 self-critical; P008/P009 no fabricated data + immutable history ("missing spins are never inferred from probability; corrections are auditable reconciliation events"); P012 willing to change its mind. The spec's phrase "observed > inferred" is the governing rule: **detect** is always allowed, **repair** only with authoritative identity, **never guess**.

## (a) Capability table

| # | Capability | RoulCollector448 implementation (files + mechanism) |
|---|---|---|
| 1 | **Raw data capture** | `collector/roulette2_collector.py` (`make_on_ws_frame`, `poll_dom`, `flush_obs`), `collector/observer.py` (`record_observation`, `flush_observations`). Every raw payload is captured two ways: (a) CDP `Network.webSocketFrameReceived/Sent` interception (15s timeout wrapper `cdp()`) parses each WS frame; a spin frame → dict appended to in-memory `state["obs_buffer"]`; (b) DOM polling fallback scrapes result elements (15 selectors) and appends `source='dom'` observations. Buffered observations flush to SQLite every 25-spin canonical save (write amplification unchanged). Format: one `spin_observations` row per observation — `observed_at, source ('websocket'|'dom'|'history'|'reconciled'|'backfilled'|'manual'), session_id, game_id, number, description, server_ts, payload_hash, raw_payload (verbatim WS JSON frame or `"selector: text"` for DOM), sequence_hint, validation_status, capture_latency, commit_latency`. Retention: no pruning code — raw rows retained indefinitely ("retain_raw_observations_for_forensic_audit"); proposal says 30-day retention configurable. Canonical data also mirrored to `state.json` + CSV (legacy export, `save_spins`). |
| 2 | **Source-of-truth preservation** | `collector/schema.py` (`spin_observations` DDL), `collector/observer.py`, `collector/repairer.py`. Raw observations are **never updated or deleted** — no code path mutates `spin_observations`; tests assert repairs "never touch observations" (`tests/test_reconstruct.py::test_never_touches_observations`). Repairs change only the canonical `roulette_spins`; the pre-repair value is preserved in the observation and in `repair_events.details` (old/new, evidence source, reason). WS history snapshots (Signal C) are persisted as `source='history'` observations so the reconciliation authority **survives restarts** (`DBHistoryProvider` reloads them from the same DB). Reparse paths: `reconstruct_ordering()` rebuilds canonical `sequence_no 1..N` from chronological evidence (server_ts → captured_at → id tie-break); `parse_history_frame()` re-parses buffered WS history payloads; `parse_history_text()` re-parses DOM history text. |
| 3 | **Validation** | `collector/validator.py` (`validate_spin` + per-check functions), wired in `roulette2_collector.py::validate_new_spin`. Pure deterministic checks, never mutates canonical data: **number** must be int 0..36; **color** must equal `num_to_color(number)` (flag, never silently fix); **game_id** present, non-whitespace, ≤128 chars; **timestamps** parseable ISO (naive treated as UTC), not >5 min future, not >1 year old; **capture latency** (observed−server) ≤120 s; **commit latency** (committed−observed) ≤300 s; **cadence** vs previous spin: negative delta = out-of-order, ≥120 s = GAP, 70–119 s = SUSPICIOUS. Cross-field check: `check_observed_contradiction` flags a source description that contradicts the number (e.g. "17 Red") as an integrity event instead of normalizing it. Outcome: `VALID | SUSPECT | INVALID` (INVALID = structurally impossible; SUSPECT = needs reconciliation); problems logged as `SPIN_INVALID`/`SPIN_SUSPECT` events. Runs in the capture path (<1 ms), never blocks, never raises. |
| 4 | **Reconciliation** | `collector/reconciler.py` (`reconcile`, `compare_windows`), `collector/history.py` (providers), `collector/roulette2_collector.py::reconcile_task` (30 s light / 60 s full), `scripts/standalone_reconcile.py` (30 s / 5 min, decoupled). Local = latest 500 canonical spins; remote = authoritative history (WS-buffered frames → durable DB history → DOM panel, probe order); both newest-first. Matching hierarchy (strongest identity wins, per record): **1 game_id, 2 server_ts+number, 3 ordered position+same number, 4 server_ts+neighbour context**. Walk newest→oldest to first divergence, then classify: **missing** (in remote, not local), **wrong value** (same identity, different number → correction), **duplicate** (EXACT/CONFLICT/TS_MISMATCH), **extra** (local-only → flagged, never deleted), **ordering** (insertion shift: uniform positive position-delta on a contiguous newest suffix → renumber whole suffix; same-set reorder: identical game_id set in different order → renumber minimal out-of-order suffix). `RepairPlan` is deterministic-only; `repairable=True` only when remote carries game_id identity (level-1 capable) — number-only DOM history can **detect** but never drive repairs. If no authoritative history: window stays UNVERIFIED, `window_achieved` reported honestly. Re-verify pass runs after every repair. |
| 5 | **Duplicate detection** | `collector/observer.py` (`payload_hash`), `collector/schema.py` (`dedup_key` + unique indexes), `collector/reconciler.py` (classification). **Three layers:** (a) observation-level: `payload_hash = sha256(json.dumps([source, game_id, number, server_ts], sort_keys=True, default=str))` + `UNIQUE(source, payload_hash)` — identical content from the same source recorded once (makes restart replay and WS join-snapshots idempotent); the same spin from *different* sources is deliberately kept as two rows (that's the cross-validation evidence). (b) canonical-level: `game_id TEXT NOT NULL UNIQUE` + storage-level `dedup_key` column (`'gid:'+game_id`, else `'tsn:'+server_ts|number` for malformed ids) with a **partial unique index** `ON roulette_spins(dedup_key) WHERE dedup_key IS NOT NULL` — a spin arriving under a different/malformed id still dedupes. `INSERT OR IGNORE` + `rowcount` gives the inserted counter ("+N new to DB"). Identity-less rows are never inserted canonically (`SPIN_NO_IDENTITY` event). (c) reconciler duplicate taxonomy for rows that already exist: **EXACT** (gid+number+ts identical → collapse), **CONFLICT** (gid same, number differs → CRITICAL incident, never silent), **TS_MISMATCH** (gid+number same, ts differs → WARNING). `Telemetry` counters `duplicates`/`conflicts`; `duplicate_incidents()` maps kinds→severity. |
| 6 | **Stale-data detection** | `scripts/watchdog_win.py` (`decide`, `data_health`), `collector/watchdog.py` (Linux), `roulette2_collector.py` (STALL_THRESHOLD_S, `write_heartbeat`), `backend/liveness.py`, `_freshness_component`. Three independent layers: **(a) liveness heartbeat** — collector writes `roulette2_heartbeat.json` every ~5 s loop tick (atomic tmp+rename) with status RUNNING/STALLED/RECOVERING/ABANDONED, latency stats, last spins; Linux uses journald lines instead. Watchdog `decide()` is a pure function: process dead → restart immediately; heartbeat >3 min stale → HUNG → kill+restart; fresh heartbeat but no spin for 10 min → NO_OUTPUT → restart; collector self-declared ABANDONED → restart; process alive + no heartbeat <3 min since boot → BOOTING (leave alone). **(b) capture stall** — `sec_since_last > 120 s` (cadence envelope max ~57 s) triggers the recovery ladder. **(c) data staleness** — freshness component of the health score: 1.0 if a spin arrived ≤3 min ago (3× cadence), linear decay to 0.0 at 15 min; dashboard `collector_alive = live_age < 180 s`; watchdog `data_health()` runs L2 reconciliation first, kill+restart only if data still unhealthy after 15 min. |
| 7 | **Sequence validation** | `collector/repairer.py` (`reconstruct_ordering`, `reorder_window`), `backend/app.py` (`rolling_verify`), `scripts/standalone_reconcile.py` (`recover_gaps`), `collector/validator.py` (`check_cadence`). Canonical order is the `sequence_no` column (default = id order at insert; `reconstruct_ordering` rebuilds 1..N from server_ts→captured_at→id when collisions/NULLs/order violations exist — deterministic and idempotent, and with `preserve_gaps=True` it preserves holes for the gap lifecycle). `rolling_verify` computes holes in the latest 500 (missing = count of absent sequence numbers in [min..max]) and `current_gap` = longest consecutive hole run. The reconciler detects **insertion shifts** (missed middle spin misaligns every newer record → renumber the affected suffix at authoritative positions) and **same-set reorders** (swap detection, minimal out-of-order suffix). `recover_gaps` turns each hole-run into a `GAP` repair event: OPEN → attempt backfill from history → re-verify → RESOLVED/REPAIRED or UNVERIFIED (permanent). Cadence check flags negative deltas as out-of-order. |
| 8 | **Timestamp validation** | `collector/validator.py` (`check_timestamp`, `LatencyTracker`), `observer.py` (`now_iso`), `backend/app.py` (`_now_iso`). All timestamps normalized: `Z` → `+00:00`, naive datetimes treated as UTC in validators (`.replace(tzinfo=utc)`); the backend compares with aware datetimes, assuming local tz for naive writer values (never a naive-vs-aware TypeError). **Monotonicity:** `check_cadence` flags negative deltas; **clock skew:** server_ts >5 min in the future → `TIMESTAMP_ANOMALY`; >1 year old flagged; **latency windows:** `capture_latency = observed_at − server_ts` (>120 s suspicious), `commit_latency = committed_at − observed_at` (>300 s suspicious), both stored per observation even for deduped spins. `LatencyTracker` keeps rolling deques (maxlen 500) of both latencies, computes P50/P95/P99/max; P99 > 10 s fires `LATENCY_HIGH` (300 s cooldown) — an early-degradation signal before an outright stall. Latency stats ride the heartbeat and `/api/health`. |
| 9 | **Anomaly detection** | `collector/validator.py` + `observer.py::log_event`, `collector/source_agreement.py`, `collector/reconciler.py` (`duplicate_incidents`), `backend/app.py` (`evaluate_alerts`, `classify_event`). Everything surfaces as a structured `integrity_events` row: `event_type` (SPIN_INVALID, SPIN_SUSPECT, TIMESTAMP_ANOMALY, GAP, OUT_OF_ORDER, DUPLICATE, CONFLICT, SOURCE_DISAGREEMENT, LATENCY_HIGH, SPIN_NO_IDENTITY, MISSING_SPIN, RECONCILIATION[_LIGHT], REPAIR_REFUSED, REPAIR_FAILED, SESSION_START/END, STALL), `severity` (INFO/WARNING/CRITICAL), `game_id`, `details` (JSON), `root_cause` (DATA, DATA_INTEGRITY, PERFORMANCE, CDP, STALL, RECONCILIATION, REPAIR, WS_DISCONNECT, OTHER). Alert rules (`evaluate_alerts`): **CRITICAL** — rolling-500 verification <100 %, unverified records >0, conflicting game_ids, duplicate game_ids, two consecutive reconciliation failures; **WARNING** — DOM/WS disagreement in last hour, ≥3 recovery events/hour, capture P99 >10 s vs P50, repair frequency doubling hour-over-hour. Root-cause classification maps event types → category + suggested action for the incident feed. |
| 10 | **Database integrity** | `collector/schema.py` (DDL + `connect()`), `collector/repairer.py` (transactions). Constraints: `color CHECK(color IN ('Red','Black','Green'))`, `game_id TEXT NOT NULL UNIQUE`, `spin_observations.UNIQUE(source, payload_hash)`, source CHECK constraint, partial unique index on `dedup_key`, NOT NULL on identity columns. **No triggers, no FKs** (SQLite; audit tables reference game_ids as plain text; the canonical table is self-contained). Writer connection: WAL, `busy_timeout=5000`, `synchronous=NORMAL`, single-writer discipline. Every repair is one explicit `BEGIN…COMMIT` with `ROLLBACK` on any failure (`apply_plan`, `_run_transaction`); capture appends (`INSERT OR IGNORE`) never conflict with repair transactions. Read-only consumers (watchdog, DBHistoryProvider) open `file:...?mode=ro`. Schema evolution is additive and idempotent: `ensure_schema()` = CREATE IF NOT EXISTS + guarded `ALTER TABLE ADD COLUMN` per column + `dedup_key` backfill BEFORE creating the unique index. **No `PRAGMA integrity_check`/`VACUUM` in code** — integrity is asserted by the app-level `rolling_verify` queries instead. |
| 11 | **Accuracy measurement** | **Data accuracy:** `backend/app.py::rolling_verify` — over the latest 500 canonical spins (sequence_no DESC, id tie-break): `verified` = rows with status VALID or REPAIRED; `missing` = sequence holes; `duplicates`/`conflicts` = game_id counts; `unverified` = other statuses; `invalid_numbers`; `perfect` = all zero. Reported as `N / N verified` (`verified_label`, `verified_window`) in `/api/integrity` and `/api/integrity/window`. **Prediction accuracy** (separate ML domain, per P002/P003): `scripts/feature_model.py` — 70/30 time-ordered split (strict, no leakage: Markov features frozen from train transitions only), `acc = mean(argmax(pred) == y_test)`, `top3/top5 = fraction of test rows where true label ∈ top-k argmax`; baselines always printed alongside (majority ≈ 0.029, Markov ≈ 0.027, uniform 1/37 ≈ 0.027, neighbor-follow ≈ 0.135 fair). Same pattern in `scripts/sequence_model.py` (GRU + M1/M2 Markov baselines, log-loss). Results to `ml/train_report.txt` / `ml/sequence_report.txt`. Spec adds rolling accuracy, log-loss, Brier, calibration, champion-challenger with OOS gates, Monte-Carlo null calibration, walk-forward. |
| 12 | **Confidence scoring** | `collector/integrity_state.py` (`DataHealthScore`, `score_band`, `RecoveryStateMachine`, `Telemetry`). Each component is a 0–1 ratio (e.g. reconciliation = 1.0 if last pass ok; sequence = 1 − renumbered/window; duplicates = 0 if any CONFLICT else 1 − dup rate; freshness decays 3→15 min). Bands (env-overridable `RC_SCORE_*`): ≥98 VERIFIED, ≥95 HEALTHY, ≥90 DEGRADED, ≥75 WARNING, <75 CRITICAL. Per-spin: `confidence` column default 0.95, repairs set 1.0; `status` on canonical rows: VALID / SUSPECT / REPAIRED / UNVERIFIED (QUARANTINED exists in the proposal only; observation-level `validation_status`: PENDING/VALID/SUSPECT/INVALID). `/api/integrity.status` = VERIFIED if last reconciliation ok, else UNVERIFIED/NO_DATA. State machine (process vs data health tracked separately): HEALTHY → SUSPECT → DEGRADED → RECONCILING → (success → HEALTHY | failure → RECOVERING → RECONCILING), transition history recorded. |

## (c) SQL schema DDL snippets (integrity columns/constraints)

```sql
-- Canonical table (fresh install; legacy DBs migrated with guarded ALTERs):
CREATE TABLE IF NOT EXISTS roulette_spins (
    id                  INTEGER PRIMARY KEY AUTOINCREMENT,
    number              INTEGER NOT NULL,
    description         TEXT NOT NULL,
    color               TEXT NOT NULL CHECK(color IN ('Red', 'Black', 'Green')),
    game_id             TEXT NOT NULL UNIQUE,          -- natural key
    server_ts           TEXT NOT NULL,
    captured_at         TEXT NOT NULL,
    created_at          TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    sequence_no         INTEGER,                        -- canonical position
    source              TEXT DEFAULT 'websocket',
    confidence          REAL DEFAULT 0.95,              -- provenance metadata
    status              TEXT DEFAULT 'VALID',           -- VALID|SUSPECT|REPAIRED|UNVERIFIED
    first_seen_at       TEXT,
    last_verified_at    TEXT,
    verification_version INTEGER DEFAULT 0,
    dedup_key           TEXT,                           -- 'gid:<id>' | 'tsn:<ts>|<n>'
    observed_at         TEXT, committed_at TEXT,
    capture_latency     REAL, commit_latency REAL
);
-- Storage-level uniqueness BEYOND game_id (malformed-id defense):
CREATE UNIQUE INDEX IF NOT EXISTS idx_spin_dedup
    ON roulette_spins(dedup_key) WHERE dedup_key IS NOT NULL;

-- Immutable raw evidence (never UPDATE/DELETE):
CREATE TABLE IF NOT EXISTS spin_observations (
    id                INTEGER PRIMARY KEY AUTOINCREMENT,
    observed_at       TEXT NOT NULL,
    source            TEXT NOT NULL
                      CHECK(source IN ('websocket','dom','history',
                                       'reconciled','backfilled','manual')),
    session_id        TEXT NOT NULL,
    game_id           TEXT, number INTEGER, description TEXT, server_ts TEXT,
    payload_hash      TEXT NOT NULL,          -- sha256([source,gid,number,server_ts])
    raw_payload       TEXT,                   -- verbatim WS frame / DOM text
    sequence_hint     INTEGER,
    validation_status TEXT NOT NULL DEFAULT 'PENDING',
    capture_latency   REAL, commit_latency REAL,
    UNIQUE (source, payload_hash)             -- content dedup, cross-source kept
);

-- Detection/action audit trail:
CREATE TABLE IF NOT EXISTS integrity_events (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    created_at TEXT NOT NULL, event_type TEXT NOT NULL,
    severity   TEXT NOT NULL DEFAULT 'INFO',   -- INFO|WARNING|CRITICAL
    game_id TEXT, details TEXT,                -- details = JSON
    root_cause TEXT                            -- DATA|DATA_INTEGRITY|PERFORMANCE|CDP|...
);

-- Repair queue + audit trail:
CREATE TABLE IF NOT EXISTS repair_events (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    created_at TEXT NOT NULL,
    incident_type  TEXT NOT NULL,              -- MISSING_SPIN|WRONG_VALUE|DUPLICATE|CONFLICT|
                                               -- OUT_OF_ORDER|GAP|RECONSTRUCT_ORDER|REPAIR_REFUSED
    start_game_id TEXT, end_game_id TEXT,
    affected_count INTEGER,
    status     TEXT NOT NULL DEFAULT 'OPEN',   -- OPEN|IN_PROGRESS|RESOLVED|FAILED|UNVERIFIED
    attempts   INTEGER DEFAULT 0,              -- retry-increment semantics
    last_attempt_at TEXT, resolved_at TEXT,
    resolution TEXT,                           -- REPAIRED|BACKFILLED|COLLAPSED|CORRECTED|
                                               -- REORDERED|REPAIR_FAILED|UNVERIFIED
    details    TEXT                            -- JSON: old/new values, evidence, reason
);
```

## (d) Notable design patterns worth copying

1. **Immutable observation ledger + mutable canonical store.** Raw evidence (`spin_observations`) is append-only; repairs rewrite only the canonical table; every canonical row traces to observations + session + source + timestamps (provenance requirement). Corrections are *events*, not edits to history. This is the single most portable pattern — a poker capture system should store every raw hand payload/hash forever and keep a separate reconciled view.
2. **"Observed > inferred" repair authority gate (Signal C).** Detection is always allowed; repair requires *identity* (a stable natural key from the source: game_id, or server_ts+number). Number-only history can detect discrepancies but can never manufacture identity to repair — this is enforced in code (`plan.repairable = any(r.game_id for r in remote)`) and as explicit refusal reasons (`NO_AUTHORITY`, `NO_IDENTITY`, `CONFLICTING_SOURCES`, `STATISTICAL_INFERENCE`) that mark rows UNVERIFIED and surface instead of silently guessing. Never-repair conditions are a named constant table, unit-tested.
3. **Deterministic matching hierarchy (4 levels).** game_id → ts+number → ordered position → ts+neighbours. Each level grants a different privilege: level 1 (game_id) = repair authority; weaker levels = detection/alignment only. The walk-newest-backwards algorithm finds the *first divergence* and repairs the affected suffix, not the whole window.
4. **Reconcile → repair → re-verify loop** ("a repair is not success until re-validation passes") — every pass ends by re-running reconciliation; the repair transaction includes a `verify_fn` that runs before COMMIT so a bad repair rolls back atomically.
5. **Explicit state machine with process/data health separation.** Browser can be alive while data is broken; the watchdog evaluates six signals (collector_alive, last_spin_age, sequence_health, reconciliation_health, repair_queue, data_health_score) and tries the *non-destructive* L2 reconcile before any kill/restart ("data before destructive").
6. **Weighted 0–100 health score with configurable weights/bands.** Six named components, each a 0–1 ratio, env-overridable thresholds — the dashboard band (VERIFIED/HEALTHY/DEGRADED/WARNING/CRITICAL) drives watchdog thresholds (score <75 → escalate).
7. **Dual dedup layers.** Content hash at observation level (`sha256` of canonicalized fields — stable across restarts) + natural-key unique index at canonical level, with a fallback identity key (`tsn:`) for malformed natural keys and a hard rule: no identity → no canonical insert, surface it.
8. **Decoupled always-on worker.** The reconcile/repair loop runs *outside* the collector process (`standalone_reconcile.py`), so the rolling 500-window keeps self-auditing during collector downtime; deep sweep every 5 min independent of capture cadence.
9. **Audit-as-database, not log files.** All detections and actions land in SQL tables with severity, root-cause category, JSON details, and retry counts — the dashboard and watchdog query the same tables, and incident feeds merge detection+resolution rows.
10. **Gap lifecycle with honest terminal states.** A gap is a first-class event: OPEN → attempt recovery from history → RESOLVED/REPAIRED (backfilled) or UNVERIFIED (permanent, surfaced as amber, never silently compressed). Sequence holes are *preserved* by `reconstruct_ordering(preserve_gaps=True)` so the recovery lifecycle can find them.
11. **Self-learning diagnostics.** When a recovery step fails (e.g. refresh selector miss), the collector dumps DOM candidates so the next incident teaches the real control instead of guessing blindly.
12. **Additive, idempotent schema migration.** `ensure_schema()` = CREATE IF NOT EXISTS + guarded ALTERs + backfill before index creation; rollback = stop collector, revert code. Schema drift is detected at runtime (`PRAGMA table_info`) so old DBs degrade gracefully (rolling_verify column-aware).
