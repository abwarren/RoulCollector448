# ADR-0001: Read-only REST API between collector DB and dashboard

**Status:** Accepted
**Date:** 2026-08-01

## Context
The dashboard needs spin data from `/home/wa/roulette2_spins.db`. Two options:
read the SQLite file directly from the frontend, or serve it through an API.
The dashboard must later run on a separate Ubuntu Server PC while the collector
stays on this box.

## Decision
A small **read-only REST API** (FastAPI) is the only data path to the frontend.
The collector and its DB remain untouched. The API also serves the static
frontend files.

## Consequences
- **Easier:** dashboard moves to the Ubuntu server by pointing it at this box's
  API over the LAN; no DB file access from remote, no code changes.
- **Easier:** SQLite stays single-writer (collector) — no multi-reader locking
  concerns, WAL-friendly.
- **Easier:** one process to deploy (API + frontend together).
- **Harder:** one more moving part locally vs. direct file reads; needs the API
  process running (systemd unit).

## Alternatives considered
- *Direct DB reads from the frontend:* impossible from a browser without an
  intermediate server anyway; rejected.
- *Static JSON dumps regenerated by cron:* no live data, races with the
  collector's per-spin writes; rejected.
